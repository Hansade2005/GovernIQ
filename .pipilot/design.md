# Design System — Regional Assembly Analytics and Archive Management — Enterprise governance & digital records platform

> Generated by the PiPilot UI director. This is THE design system for this app — follow it EXACTLY on every file. Do not re-derive or re-read; it's already in your context.

## Aesthetic direction
refined-minimal-with-institutional-warmth
Signature element (the one memorable thing): archive-spine-accent: a thin burnt-sienna left border on every record card, echoing physical filing cabinets and evoking institutional memory—visible on hover with a subtle expand animation

## Color tokens (CSS variables — define :root and .dark)
```css
:root {
  --background: oklch(98% 0.002 262); --surface: oklch(96% 0.004 262); --surface-alt: oklch(92% 0.006 262);
  --foreground: oklch(18% 0.03 262); --muted: oklch(48% 0.02 262); --border: oklch(88% 0.008 262);
  --primary: oklch(42% 0.12 262); --primary-light: oklch(72% 0.08 262); --accent: oklch(62% 0.18 29); --ring: oklch(42% 0.12 262);
  --on-primary: #ffffff; --on-accent: #ffffff; /* text ON the brand/accent bg — flip to a near-black only if that color is pale */
}
.dark {
  --background: oklch(16% 0.04 262); --surface: oklch(22% 0.04 262); --surface-alt: oklch(22% 0.04 262);
  --foreground: oklch(96% 0.003 262); --muted: oklch(72% 0.02 262); --border: oklch(32% 0.04 262);
}
```
One dominant brand color + one sharp accent — never a timid evenly-spread palette. Wire dark mode from the start.
**Contrast check (do this, don't skip):** every text/bg pair must clear WCAG AA in BOTH themes — foreground text on `--background` and on `--surface`, `--muted` text (still readable, not washed out), placeholder text, button labels on `--primary`/`--accent` (`--on-primary`/`--on-accent` flip to near-black only if that brand color is pale), and borders visible against their surface. NEVER white-on-white, dark-on-dark, or a mid-gray that vanishes. Keep `background` → `surface` → `surface-alt` visibly stepped so cards separate from the page. The accent must POP against the background, not blend or clash.

## Non-negotiables — make it powerful, unique, and correct
These are HARD rules. Apply them on every screen.

### Contrast & color pairing (never get this wrong)
- Text must ALWAYS contrast strongly with whatever is behind it: WCAG AA — ≥4.5:1 body, ≥3:1 large/headings. Verify EVERY text-on-background pair.
- Pick the foreground from the BACKGROUND'S lightness: light/near-white text on dark or saturated/vivid backgrounds (brand color, accent, colored cards, hero image overlays); dark text on light surfaces. On a vivid orange/red/blue/green button or banner → WHITE/near-white text, NEVER dark text. On a white/light card → the DARK foreground, NEVER white or another light color. No white-on-white, no light-gray-on-white, no dark-on-dark.
- Define + USE on-color tokens: `--on-primary` / `--on-accent` (usually #fff for vivid brand colors; a near-black only if the color is pale). Any button/badge/chip/section using the brand or accent as its background MUST set its text to the matching on-* token.
- Never rely on near-equal luminance (mid-gray on mid-gray, pastel on white). When unsure, increase contrast.
- Examples — do this, not that:
  - Good: button on the brand color → `class="bg-[--primary] text-[--on-primary]"` (white on vivid). Bad: `bg-[--primary] text-[--foreground]` when foreground is dark — dark-on-orange is unreadable.
  - Good: text on a light card → dark `text-[--foreground]` on `bg-[--surface]`. Bad: white/light text on a white/light card (invisible).
  - Good: text over a photo → add a `bg-black/50` overlay, then white text. Bad: raw light text directly over a bright/busy image.
  - Good: a big HERO HEADING on a light/cream hero → the DARK ink/foreground token (or, for a gradient title, a dark→saturated-brand gradient that stays readable). Bad: white/near-white or a pale-tint heading on a light section, and `bg-clip-text text-transparent` with a light-to-light/pastel gradient — both render as an invisible near-white headline (the #1 hero bug). Light heading text is ONLY for dark or image/overlaid hero backgrounds.

### Imagery — REAL images only, never broken
- Use real images wherever they help (hero, features, cards, avatars, testimonials, og). GENERATE them with the generate_image tool into public/… and reference the local path — this is the default and most reliable.
- NEVER use `source.unsplash.com/random`, `unsplash.it`, `placeholder.com`, `via.placeholder`, picsum `/random`, or any URL that redirects/expires — they render as broken images. If you must use stock, use a STABLE direct CDN URL to a SPECIFIC asset id, not a random endpoint.
- Always set width/height (or aspect-ratio) + object-cover + a tasteful loading state so images never cause layout shift or blank boxes.

### Icons — a real icon library, NEVER emojis
- Do NOT use emojis as UI (icons, bullets, buttons, feature markers, statuses, headings). They look unprofessional and render inconsistently across platforms.
- Use a proper icon set: lucide-react: Archive, FileText, ChevronRight, Lock, AlertCircle, CheckCircle, Clock, Users, BarChart3, Settings, Download, Share2, Filter, Search, Calendar, MapPin (default lucide-react), or Material Symbols / Heroicons / Phosphor / Tabler. ONE library per project, consistent size + stroke, currentColor, optically aligned to text.

### Motion — animated, intuitive, alive (Framer Motion)
- Use framer-motion for orchestrated entrance reveals, hover/press feedback, layout transitions, list reordering, and page/route transitions. Fast (150–300ms), eased, transform/opacity only.
- ALWAYS respect prefers-reduced-motion. Motion guides attention and feels premium — never gratuitous.

### Delight — celebrate success (confetti)
- Fire canvas-confetti (or a framer-motion burst) on meaningful SUCCESS: form submitted, signup complete, payment succeeded, a goal/streak reached, onboarding finished. ONE brief tasteful burst, then settle — paired with a clear success state/message.

### The bar — top-notch, unique, unmatched
- Every site must feel bold, premium, and one-of-a-kind — never generic or templated. Commit hard to the aesthetic direction above: the characterful display+body font pairing with a strong type scale + tight heading tracking, generous intentional whitespace, layered depth (soft shadows + subtle gradient/grain/glow over flat fills), and the signature element. Smooth, beautiful typography is non-negotiable.
- Design every state: hover, focus-visible, active, disabled, loading (skeletons), empty (with a CTA), error. Make it something people screenshot.

Apply this system to EVERY component and page. Reuse tokens + primitives everywhere for perfect consistency.
